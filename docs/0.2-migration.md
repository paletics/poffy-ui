# Migrating to 0.2

Poffy UI is still pre-1.0. Minor releases may intentionally refine public API
contracts while the component model is being stabilized. Treat `0.2.0` as the
compatibility boundary for the changes below.

## Structural composition contracts

`core.grid` documents remain node version 1. No persisted-document migration is
required: legacy `{ columns: N }` nodes retain their fixed-column meaning.
New documents should use the responsive contract by default:

```ts
{ type: 'core.grid', version: 1, props: { mode: 'responsive', minChildWidth: 'md' } }
```

Use `{ mode: 'fixed', columns: N }` only when a fixed 1–12 column count is
intentional. `minChildWidth` accepts only `sm`, `md`, or `lg`; arbitrary CSS
lengths remain outside the serialized screen contract.

- `Stepper` counts only direct `Step` children. Replace components that merely
  return a `Step` with a direct `Step`, and wrap non-step content in
  `StepperAuxiliary`.
- `List.Root` no longer wraps opaque components in an implicit `li`. Render
  `List.Item`, a native `li`, or a component that forwards to one of those
  hosts. Known-invalid native and text children still receive a safety wrapper.
- `Divider` no longer accepts `asChild`; style or wrap its fixed semantic `hr`
  instead.
- `SearchInput` no longer accepts InputGroup-owned `startElement`,
  `endElement`, interactive-slot, `children`, `type`, or `asChild` props.

Ambiguous duplicate values now fail closed in MultiSelect and WheelPicker.
Ensure MultiSelect option values, WheelPicker column IDs, and option values
within each WheelPicker column are unique.

CircleProgress and AvatarGroup no longer accept opaque custom `asChild` hosts.
Use their documented native hosts. Delegated Badge, Stat, progress indicator,
Spinner, AvatarGroup, and motion-wrapper event/ref types now describe the
actual delegated host; remove callback annotations that incorrectly require
the former default `div`, `span`, or `ul` target.

Puff's provider lifecycle fields are no longer public component props. Remove
`removePuff`, `isVisible`, and `onExitComplete` from standalone `Puff` usage.
The public `id` prop now becomes the rendered DOM `id`; provider identity and
exit finalization remain internal to `PuffProvider`.

## Image alternative text

`Image` now requires either explicit alternative text or explicit decorative
intent:

```tsx
<Image src="/profile.jpg" alt="Profile" />
<Image src="/texture.png" decorative />
```

An empty `alt` remains valid native HTML for decorative images. Do not combine
`decorative` with `alt`.

## Icon `asChild`

`Icon asChild` now accepts only a native SVG or a custom component that renders
an SVG host. Wrap non-SVG content separately instead of styling it as an icon:

```tsx
// Before
<Icon asChild>
  <span>★</span>
</Icon>

// 0.2
<span className={iconTextClass}>★</span>
```

SVG integrations are unchanged:

```tsx
<Icon asChild>
  <CustomSvg />
</Icon>
```

## OTPInput

`OTPInput` owns its segmented semantic structure and no longer accepts the
ignored `asChild` prop. Use `className` or an external wrapper for layout.
The unused `messages.verificationCode` override is also removed; customize
per-segment names with `messages.digit`.

Controlled and uncontrolled values are now fixed-position segment arrays.
Empty strings preserve holes when a middle segment is cleared; `onComplete`
and the native form value still expose the joined code. A form reset restores
the latest `defaultValue`:

```tsx
const [segments, setSegments] = useState(['', '', '', '', '', '']);

<OTPInput name="verificationCode" value={segments} onChange={setSegments} />;
```

## Read-only required selection controls

Read-only `Switch`, standalone `Checkbox`, and `RadioGroup` controls continue to
announce their required state, but no longer participate in native constraint
validation while the user cannot change their value. Selected values still
participate in form submission. Removing `readOnly` restores the native
`required` constraint.

`Checkbox.Group required` now validates only selected checkbox inputs that are
currently mounted, enabled, unambiguous, and associated with the group form.
Controlled or default values that have no participating checkbox remain in the
value array, but they no longer satisfy the required constraint. Mounting or
enabling the matching checkbox makes the group valid without emitting
`onChange`.

## Slider required state

`Slider` no longer accepts `required` or `aria-required`. A native range input
always has a value, so those attributes cannot represent an unselected state
and do not provide meaningful constraint validation.

Do not put a Slider inside a required FormControl merely to require user
interaction. Validate the business rule explicitly, or use a control with a
real empty state such as Checkbox or NumberInput.

## RadioGroup names in SSR and no-JavaScript forms

`RadioGroup` now requires an explicit `name` whenever native grouping,
constraint validation, or form submission must work in server-rendered markup
without JavaScript. Omitting `name` intentionally emits no named radio controls
on the server, preventing an implicit internal field from leaking into form
payloads. After hydration, a client-only internal name supports interactive
grouping, but it is not a no-JavaScript form contract.

## Fixed semantic upload and tree content

`FileUploader` and `FileUploader.Root` own the managed uploader root, native file
input, and validation proxy. Their previously ignored `asChild` prop is removed.
Use `className`, the compound uploader parts, or an external wrapper:

```tsx
<section className={uploadLayoutClass}>
  <FileUploader className={uploaderClass} />
</section>
```

`helperText` belongs to the shorthand `FileUploader` or to
`FileUploader.Zone`. It is no longer accepted by the compound root:

```tsx
<FileUploader.Root>
  <FileUploader.Zone helperText="PDF files up to 5 MB" />
  <FileUploader.List />
</FileUploader.Root>
```

The shorthand owns its generated Zone and List and therefore no longer accepts
children.

`TreeView.Content` likewise owns its nested `<ul role="group">` and collapse
structure and no longer accepts the ignored `asChild` prop. Use `className` or
wrap the content externally when additional layout is needed. Other TreeView
parts retain their documented, semantically constrained `asChild` support.

The same fixed-host contract now applies to these components:

- `Breadcrumbs`, `Breadcrumbs.Item`, and `Breadcrumbs.Separator`
- `Sidebar`, `Sidebar.Header`, `Sidebar.Content`, `Sidebar.Footer`, and
  `Sidebar.Group`
- `ScrollArea`

Their ignored public `asChild` props are removed. Their semantic root elements
remain fixed; use an external wrapper when another layout or landmark is needed.
`FixedSemanticProps` is removed from `@poffy-ui/types`; use `NativeProps` for a
fixed host and `PrimitiveProps` only for components that actually delegate with
`asChild`.

## Managed composite semantics

Composite roots now exclude attributes whose values are owned by their
interaction contract:

- `OTPInput`, `ButtonGroup`, `Checkbox.Group`, `RadioGroup`, `TimePicker`,
  `TimeClock`, and `Stepper` own their root role.
- `OTPInput`, `TimePicker`, and `TimeClock` derive `aria-disabled` from
  `disabled`.
- `RadioGroup` derives `aria-orientation` from `orientation` and
  `aria-readonly` from `readOnly`.
- `DatePicker` owns native date-input semantics or its custom button trigger,
  popup state, dialog relation, invalid state, and localized required
  announcement.
- `Slider` owns its native range role, orientation, numeric value semantics,
  and disabled and read-only announcements. `required` and `aria-required` are
  removed because a range input has no meaningful empty state.
- `Switch` owns its checkbox type, switch role, checked semantics, and derived
  disabled, read-only, and required announcements.
- `DateTimePicker`, `RangeSlider`, and `WheelPicker` own their composite group
  roles and derive group disabled state. Range and wheel pickers derive
  read-only state on their slider and listbox widgets; `aria-readonly` is not
  valid on their outer `group` roles.
- Block `Code` owns its `pre > code` structure and named overflow-group role,
  so its ignored `asChild` prop is removed. Inline `Code` still accepts
  `asChild` and a meaningful custom role.
- Tabs own the tablist, tab, and tabpanel roles, orientation, selection,
  trigger/panel ID relationships, panel visibility, and the internal occurrence
  metadata used to build those relationships. The fixed Tabs root, TabList, and
  TabContent no longer expose their previously ignored `asChild` prop. Keep one
  directly inspectable `TabList`, put triggers inside it, and put panels outside
  it. Fragments and native wrappers are supported. Duplicate values, invalid
  placement, and opaque component wrappers fail closed during SSR; opaque
  wrappers are retained only as client-side compatibility after registration.

Remove those redundant native attributes from callers. Meaningful inputs such
as accessible names and descriptions, `aria-invalid`, `aria-required`,
`TabTrigger` disabled state, and panel `aria-label` remain supported. Wrap a
component externally if a different semantic structure is required.

`TabTrigger asChild` no longer forwards native button-only attributes such as
`type`, `form`, `formAction`, `formMethod`, `formTarget`, `name`, or `value` to
a delegated non-button host. Put any host-specific attributes on the child
itself. The default button branch continues to accept native button attributes.

## DatePicker trigger and ref contract

The default custom `DatePicker` is now an input-styled `HTMLButtonElement` that
opens a calendar dialog. Its selected value is visible button text rather than
an input `.value`, and its ref and DOM event `currentTarget` are
`HTMLButtonElement`.

`native={true}` continues to render a platform date `HTMLInputElement`; its ref
and native input events remain input-based. Code that previously queried the
custom picker as a `combobox`, read `.value`, or stored an
`HTMLInputElement` ref must move to the button-and-dialog contract.

Custom mode owns `aria-expanded`, `aria-haspopup="dialog"`, the dialog
relationship, invalid state, and required descriptions. Selecting the current
calendar day is a semantic no-op and does not call `onChange` again.

## Owned compound props

Compound component slots no longer expose values owned by their root:

- `InputGroup.Input` takes its `size` from `InputGroup`.
- `Radio` takes `checked`, `defaultChecked`, `name`, `form`, `onChange`, and its
  native role/checked/disabled semantics from `RadioGroup`.
- `Checkbox.Input` takes `checked`, `defaultChecked`, `disabled`, `onChange`,
  `value`, and its native role/checked/disabled semantics from `Checkbox`.

Move those values to the corresponding root. `Skeleton` now accepts children
only with `asChild={true}`, where exactly one native `div`, `output`, or `span`
is required. A normal Skeleton is the loading placeholder itself and has no
rendered child. Skeleton owns `aria-hidden` and `inert`; remove caller
overrides.

`EmptyState.Icon` is presentation-only. Move click, keyboard, pointer, focus,
editable, and drag behavior to `EmptyState.Actions`. Meaningful icons still
require an accessible name; their visual subtree is isolated from interaction.

`Breadcrumbs.Link isCurrentPage` renders a non-interactive span. Remove anchor
navigation attributes and activation handlers from that branch; keep them only
on ordinary breadcrumb links.

## Brand configuration

A custom brand must now be configured atomically:

Runtime calls with an unknown built-in brand or an incomplete custom palette
are ignored. Use `setBrand('blue' | 'pome')` for built-ins and
`setCustomBrand({ main, ... })` to activate a validated custom palette.

```tsx
<ThemeProvider defaultBrand="custom" customBrand={{ main: '#8b5cf6' }}>
  <App />
</ThemeProvider>
```

Built-in brands no longer accept `customBrand`, and a custom brand without a
palette is a type error. `useBrand().setBrand` switches only to built-in brands;
use `setCustomBrand(colors)` to install and activate a custom palette.

## Input appearances

Input-family recipe `variant` props are replaced by the canonical `appearance`
prop. Responsive conditional values remain supported.

| Before              | 0.2                    |
| ------------------- | ---------------------- |
| `variant="outline"` | `appearance="outline"` |
| `variant="filled"`  | `appearance="soft"`    |
| `variant="flushed"` | `appearance="flushed"` |
| `variant="neo"`     | `appearance="neo"`     |

`neo` remains limited to Select, MultiSelect, ComboBox, and ListboxSelect.
Input, Textarea, DatePicker, NumberInput, TimePicker, and DateTimePicker support
`outline`, `soft`, and `flushed`.

```tsx
<Input appearance={{ base: 'outline', md: 'flushed' }} />
<ComboBox appearance={{ base: 'soft', lg: 'neo' }} />
```

`NumberInput` now owns its fixed native semantics. Remove `type="number"` and
`role="spinbutton"` from callers; the component always renders both internally.
Its stacked stepper buttons always preserve a minimum 24 by 24 pixel target.
If an existing use depends on another `type` or `role`, migrate to `Input` or a
custom composite. `Input inputMode="numeric"` requests a numeric keyboard but
retains native string values and input-event semantics.

## Logical action icons

`Button` and `ToggleButton` icon props now describe logical inline placement so
they follow the document direction:

| Before      | 0.2         |
| ----------- | ----------- |
| `leftIcon`  | `startIcon` |
| `rightIcon` | `endIcon`   |

In left-to-right content, `startIcon` appears on the left and `endIcon` on the
right. Those visual positions reverse in right-to-left content without changing
the component props.

## Delegated host contracts

`IconButton`, `DisclosureIconButton`, `DirectionalButtonGroup`,
`FormHelperText`, and `FormErrorMessage` now publish separate default-host and
delegated-host ref and event types. Delegation is limited to hosts that preserve
each component's semantics:

- disclosure controls remain action controls;
- directional button groups use passive `article`, `div`, or `section` hosts;
- helper and error messages use passive text containers.

Replace link-like disclosure hosts and interactive form-message hosts with an
external wrapper or the component's default host.

Custom router links using a `to` destination are now preserved by `Link`,
`NavbarBrand`, and `NavbarLink`. The router component must render an anchor and
forward DOM props and its ref. Poffy does not convert `to` into `href`.

When `Link`, `NavbarBrand`, or `NavbarLink` has no `href` and its delegated
child does not provide a destination, the safe fallback is a `span`. Anchor-only
attributes such as `download`, `hrefLang`, `media`, `ping`,
`referrerPolicy`, and anchor `type` are no longer forwarded to that fallback.
Move those attributes and the destination to the router-link child, or provide
an outer `href`.

## Iterable React children

Single-use and nested iterable children are now materialized before a component
needs to inspect or render them more than once. This affects directional button
labels, CodeViewer captions, ProgressBar labels, tooltip content, context-menu
item content, CircleProgress labels, and Spinner fallback content. Generators
must still yield stable keyed elements when they produce multiple elements.
Progress/status labels are passive content contracts: opaque custom components
whose rendered output cannot be inspected are reduced to their explicit child
content or omitted. Pass text or native passive elements when the label must be
measured and displayed.

Pagination no longer emits `onChange` when the already-current page is
activated. A current-page `href` supplied by `getHref` remains navigable.

## Fixed non-submit actions

`IconButton`, `CloseButton`, `DirectionalButton`, `CopyButton`, and
`TagCloseButton`, `PopoverTrigger`, and `PopoverClose` own `type="button"` and
no longer expose the native `type` prop. Remove `type="button"` from callers.
These controls represent local UI actions and cannot be changed into submit
controls; use `Button` for a form submission action.

`CloseButton`, `CopyButton`, and `ToggleButton` now accept only button-compatible
delegated hosts. A link-like `asChild` child (`href` or `to`) falls back to the
native button host because these controls perform exclusive local actions.
`DirectionalButton` keeps a link-like child when navigation is the intended
action.

`Button`, `ButtonPrimitive`, and `DirectionalButton` no longer forward
wrapper-owned native button attributes such as `form`, `formAction`, `name`,
`type`, or `value` through `asChild`. Put native button attributes on the
delegated button child. `DirectionalButton` also stops injecting `disabled` and
`type="button"` into delegated router-link hosts with `href` or `to`; disabled
navigation remains blocked through owned activation guards and
`aria-disabled`.

The same action-host boundary applies to `IconButton`,
`DisclosureIconButton`, and `Dropdown.Item`: disabled navigation hosts do not
retain an active destination. Custom button hosts must forward the owned
`type="button"` and `disabled` props. Native form-only props such as `form`,
`formAction`, `name`, and `value` are not delegated from these action
components; use `Button` when those submission semantics are required.

```tsx
// Before: a local action was delegated to a navigation host
<CloseButton asChild>
  <a href="/dismiss">Dismiss</a>
</CloseButton>

// 0.2: use a button-compatible host for local actions
<CloseButton asChild>
  <MyButtonHost>Dismiss</MyButtonHost>
</CloseButton>

// Directional navigation remains a link
<DirectionalButton direction="next" asChild>
  <a href="/next">Next</a>
</DirectionalButton>
```

Default branches expose `HTMLButtonElement` refs and button event targets.
Valid delegated branches expose `HTMLElement` refs and event targets.

`SidebarItem asChild` follows the same destination ownership contract as Link
and NavbarLink. When the wrapper supplies `href`, it retains the full anchor
API. When the destination comes from the child, put `download`, `hrefLang`,
`media`, `ping`, `referrerPolicy`, and anchor `type` on that child. Passive
SidebarItem and Reference fallbacks discard anchor-only attributes.

## Dropdown ownership and passive slots

Dropdown now owns the trigger, menu, and item roles, generated relationships,
identity, and roving focus props. Remove caller-provided `role`, `tabIndex`,
`aria-expanded`, `aria-haspopup`, `aria-controls`, menu `id`, and item
`aria-disabled`; use `disabled` on `Dropdown.Item`.

Dropdown state is now an explicit controlled/uncontrolled union in both React
and `@poffy-ui/behavior`: passing `open` requires `onOpenChange`. Omit `open`
when Dropdown should own its state.

`Dropdown.Trigger` and `PopoverTrigger` accept opaque custom components only
under a button-compatible prop/ref forwarding contract. Native anchors are
converted into non-navigating buttons, but custom or router components carrying
`href`, `to`, or `role="link"` now fall back to the native button. Use a
`Dropdown.Item asChild` router link for navigation:

```tsx
<Dropdown.Item asChild>
  <RouterLink to="/settings">Settings</RouterLink>
</Dropdown.Item>
```

Delegated trigger `disabled`, `tabIndex`, popup relationships, and accessible
fallback name are now owned by Dropdown or Popover. Move those values to the
trigger itself instead of its child.

`Dropdown.Label asChild` accepts only passive native text or heading hosts.
`Dropdown.Separator asChild` accepts only passive `div` or `hr` hosts.
Interactive or opaque hosts fall back without retaining their interactive
subtree.

## Semantic responsive variants

`Code.variant` is now scalar because it controls the rendered HTML structure:
inline code renders `code`, while block code renders `pre > code`. Move
responsive layout styling to a wrapper instead of passing a responsive object
to `variant`.

## Visual alias removal

Legacy visual aliases are removed in favor of the shared `appearance` and
`intent` vocabulary:

| Component                | Before                          | 0.2                                           |
| ------------------------ | ------------------------------- | --------------------------------------------- |
| Card                     | `variant="elevated"`            | `appearance="solid"`                          |
| Card                     | `variant="outlined"`            | `appearance="outline"`                        |
| Card                     | `variant="filled"`              | `appearance="soft"`                           |
| Accordion                | `variant="pop"`                 | `appearance="soft"`                           |
| Accordion                | `variant="outline"`             | `appearance="outline"`                        |
| Tabs                     | `variant="line"`                | `appearance="ghost"`                          |
| Tabs                     | `variant="pill"`                | `appearance="soft"`                           |
| Tabs                     | `variant="enclosed"`            | `appearance="outline"`                        |
| Sidebar                  | `variant="floating"`            | remove the prop (floating is the only layout) |
| TreeView                 | `variant="default"`             | `appearance="soft"`                           |
| TreeView                 | `variant="ghost"`               | `appearance="outline"`                        |
| Alert                    | `variant="left-accent"`         | `variant="start-accent"`                      |
| Result                   | `status="error"`                | `intent="danger"`                             |
| Result                   | `status="success"`              | `intent="success"`                            |
| Result                   | `status="warning"`              | `intent="warning"`                            |
| Result                   | `status="info"`                 | `intent="info"`                               |
| Spinner / CircleProgress | `variant={intent}`              | `intent={intent}`                             |
| Skeleton                 | `variant={intent}`              | `intent={intent}`                             |
| Tag                      | `variant="outline"`             | `appearance="outline"`                        |
| Tag                      | `variant="solid"` or `"subtle"` | `appearance="soft"`                           |
| Tag                      | `colorScheme="gray"`            | `intent="secondary"`                          |
| Tag                      | `colorScheme="red"`             | `intent="danger"`                             |
| Tag                      | `colorScheme="green"`           | `intent="success"`                            |
| Tag                      | `colorScheme="blue"`            | `intent="info"`                               |

EmptyState now exposes `appearance="soft" | "outline" | "solid" | "elevated"`
directly: migrate `flat` to `soft`, `dashed` to `outline`, and keep `solid` or
`elevated` under the new prop name. ProgressBar uses `intent` for semantic
color and `appearance` for its surface. The old color-like `outline` and
`ghost` variants have no exact one-prop visual equivalent; choose the intended
semantic color explicitly, then use `appearance="outline"` or `"soft"`.

ProgressBar visual content moved from `children` to `label`. `children` is now
reserved exclusively for the `asChild` outer host.

```tsx
// Before
<ProgressBar progressPercent={64} showProgress>
  Uploading
</ProgressBar>

// 0.2
<ProgressBar progressPercent={64} showProgress label="Uploading" />

// Delegated outer host
<ProgressBar asChild progressPercent={64} showProgress label="Uploading">
  <section />
</ProgressBar>
```

The default branch exposes an `HTMLSpanElement` ref. The delegated branch
exposes an `HTMLElement` ref and requires an HTML flow-container host that
forwards its props and ref. With `labelPosition="auto"`, measurable text/native
label content may move inside the fill. Opaque custom label component output is
not rendered because it cannot be verified as passive or measured without
executing it twice; pass its text/native passive content to `label` instead.
`role`, `aria-valuenow`, `aria-valuemin`, and `aria-valuemax` are owned by the
internal progressbar and are no longer accepted on the outer host.

## InputGroup logical slots

Physical `Left*` and `Right*` exports are removed. Use logical slots so the
composition follows text direction:

```tsx
<InputGroup>
  <InputGroup.StartAddon>https://</InputGroup.StartAddon>
  <InputGroup.Input aria-label="Website" />
  <InputGroup.EndElement>
    <Icon />
  </InputGroup.EndElement>
</InputGroup>
```

The standalone replacements are `InputStartAddon`, `InputEndAddon`,
`InputStartElement`, and `InputEndElement`.

## Portal provider scopes

`Portal.scopeMotion` is removed. Use `scopeProviders` to recreate motion, brand,
color mode, locale, direction, and runtime token override DOM scopes at the destination:

```tsx
<Portal scopeProviders>{content}</Portal>
```

This opt-in adds neutral scope wrappers and should not be used where an
additional wrapper would invalidate native table or list structure.

## Popover

Manual Popovers are explicitly controlled:

```tsx
<Popover triggerMode="manual" open={open} onOpenChange={setOpen}>
  {/* anchor and content */}
</Popover>
```

`PopoverProps` is a discriminated union. Extend a specific branch or use a type
intersection instead of declaring an interface that extends the union:

```ts
import type { ManualPopoverProps } from '@poffy-ui/react/overlay';

interface ProductPopoverProps extends ManualPopoverProps {
  productId: string;
}
```

Click-triggered Popovers also distinguish controlled and uncontrolled state.
Passing `open` requires `onOpenChange`; omit `open` for uncontrolled usage.
Untyped JavaScript callers that still pass `open` alone receive a development
warning and an uncontrolled initial state, so dismiss actions no longer freeze.
PopoverTrigger owns `aria-expanded`, `aria-haspopup`, and `aria-controls`, and
PopoverContent owns its dialog role.

Popover triggers are disclosure actions rather than navigation targets. Replace
router-link trigger hosts with a button-compatible custom component; link-like
custom hosts now use the safe native-button fallback.

Modal, Drawer, and Tooltip now expose the same explicit state split. Passing
`open` requires `onOpenChange`; omit `open` for uncontrolled usage. Modal and
Drawer accept `defaultOpen`. Consumers that extend a branch can import
`ControlledModalProps`, `UncontrolledModalProps`, `ControlledDrawerProps`,
`UncontrolledDrawerProps`, `ControlledTooltipProps`, or
`UncontrolledTooltipProps`.

MessageModal now preserves the same state split instead of flattening Modal's
union through `Omit`. Use `ControlledMessageModalProps` or
`UncontrolledMessageModalProps` when extending its API.

Untyped legacy code that passes `open` without a callback is treated as
uncontrolled with `open` used only as its initial state, and emits a development
warning. Add `onOpenChange` when later prop updates must control visibility.

AlertDialog and HoverCard use the same controlled/uncontrolled split. CommandMenu
applies it independently to visibility and its search query: `open` requires
`onOpenChange`, and `query` requires `onQueryChange`. Untyped `open`-only or
`query`-only usage falls back to an uncontrolled initial value with a development
warning. Controlled branches cannot also pass `defaultOpen` or `defaultQuery`.
The exported `useCommandMenuState` behavior hook follows the same two-axis
controlled/uncontrolled contract.

Multiple CommandMenu instances that share a shortcut target arbitrate the
shortcut through `globalShortcutPriority`; the highest priority wins. Equal
priorities use the latest stable registration and emit a development warning,
so assign explicit priorities when nested or colocated menus share a target.

Modal, Drawer, and AlertDialog triggers own their button type, role, focus
position, disabled announcement, and popup relationships. Remove consumer
`type`, `role`, `tabIndex`, `aria-disabled`, `aria-expanded`, `aria-haspopup`,
and `aria-controls` props from these triggers. Delegated SVG, table-structure,
interactive-descendant, and link-like custom hosts fall back to a native button;
use a button-compatible HTML or custom host for direct delegation.

Generic Popover now always owns the non-modal dialog pattern and no longer
accepts `floatingRole`. Use Dropdown or ContextMenu for menus, Tooltip for
tooltips, and ListboxPopover for listboxes.

The empty generated-recipe alias `PopoverVariants` is removed. Popover has no
public recipe variants; use `PopoverProps` or a specific controlled branch type.

`Popover.Content` enables focus management by default. Composites that own their
complete focus and Tab-order behavior may explicitly pass
`focusManagement={false}`.

## ContextMenu

An open ContextMenu must have either `position` or `target`. A menu can be
mounted without an anchor only when it is statically closed:

```tsx
<ContextMenu open={false} items={items} onClose={closeMenu} />
```

ContextMenu now supplies a localized accessible fallback name. Continue to pass
`aria-label` or `aria-labelledby` when a domain-specific name is more useful.
Action item `label` values are now strings so every menuitem has a stable
accessible name. Put non-text presentation in the separate `icon` field.

The unimplemented `type: "submenu"` and item `children` fields are removed.
Use a regular action item or open a separately managed ContextMenu until a
complete nested-menu contract is available. Untyped legacy submenu entries are
ignored instead of being converted into inert action items.

`ContextMenuCombinedProps` is removed. Use `ContextMenuProps`, which is now the
sole public root props contract.
ContextMenu also owns its `role="menu"`; remove caller-provided root roles.

## Announcement and selection defaults

- Alert now derives its omitted `live` value from `status`: errors are
  assertive alerts, while info, success, and warning messages are polite
  statuses. Pass `live="assertive"` to preserve the former behavior.
- Result no longer creates a live region when `live` is omitted. Pass
  `live="polite"` to preserve announcements for asynchronously mounted results,
  or `live="assertive"` for critical failures.
- DateTimePicker now requires a date before enabling time controls by default.
  Pass `requireDateBeforeTime={false}` only when intentionally adopting the
  current local date for time-first entry.
- EmptyState.Icon is decorative when `decorative` is omitted. A meaningful icon
  must pass `decorative={false}` and an accessible name. Its default branch
  forwards an `HTMLDivElement` ref; `asChild` accepts a native SVG and forwards
  an `SVGSVGElement` ref. Invalid delegated hosts fall back to an empty,
  decorative div rather than retaining an interactive subtree.
- StatArrow is decorative when `decorative` is omitted. A meaningful trend
  image must pass `decorative={false}` with either `aria-label` or
  `aria-labelledby`. StatArrow owns `role` and `aria-hidden`; remove both from
  consumer props.
- `TreeView.Item` is a leaf when `hasChildren` is omitted. Every expandable or
  lazy-loaded branch must pass `hasChildren`.

```tsx
<StatArrow type="increase" />
<StatArrow
  decorative={false}
  type="decrease"
  aria-label="Revenue decreased"
/>
```

## ComboBox compound ownership

The flat `ComboBox` facade no longer accepts compound children. Keep ordinary
option-array usage on `<ComboBox />`; move manual composition to
`<ComboBox.Root>`. Option values must be unique.

Selection and filter text are independent controlled axes. Supplying `value`
requires `onChange`, and supplying `inputValue` requires
`onInputValueChange`. Do not combine a controlled prop with its corresponding
`default*` prop.

ComboBox now owns the native input, listbox, and option props derived from root
state. Remove `value`, `defaultValue`, `onChange`, `disabled`, `readOnly`, `id`,
`role`, and managed combobox ARIA props from `ComboBox.Input`. Remove `id`,
`role`, and `aria-labelledby` from `ComboBox.List`, and remove option IDs,
roles, selection ARIA, managed data-state markers, and `optionIndex` from
`ComboBox.Item`.

For delegated Input and ComboBox.Input hosts, root/FormControl state now
overrides contradictory child `disabled`, read-only, required, value, popup,
focus, and relationship attributes. Keep accessible names on the wrapper input
props; description IDs continue to merge.

`ComboBox.List` now forwards its public ref to the outer listbox host rather
than the private inner `ul` presentation wrapper. Manual item DOM order may
differ from the root `options` array; generated option IDs remain associated
with the matching option value.

Form reset restores ComboBox selection and filter text independently.
Controlled axes retain their current value, uncontrolled text returns to the
latest `defaultInputValue`, transient open/highlight state clears, and reset
does not call selection or input callbacks.

ListboxSelect continues to support duplicate option values like native
`select`. Uncontrolled state preserves the selected occurrence rather than
jumping to the first equal value; controlled state and orphan-value fallback
remain aligned with the native field, FormData, and constraint validation.

Radio values must be unique. Directly inspectable duplicates fail closed during
SSR, while dynamically registered duplicates fail closed after collection
updates. Supply an explicit `name` when native no-JS grouping or form
participation is required. An omitted name denotes a client-only, non-form
group and does not promise progressive-enhancement form semantics.

## Fixed Stack aliases

`HStack` and `VStack` no longer expose the ignored `direction` prop. Use
`HStack` for a fixed row, `VStack` for a fixed column, and `Stack` when the
direction must be configurable or responsive.

Default Stack refs target `HTMLDivElement`. With `asChild`, Stack, HStack, and
VStack refs target the delegated DOM `Element`, including SVG hosts; type
generic delegated refs as `Ref<Element>`.

Box, Flex, Wrap, Center, Container, Grid, and AspectRatio follow the same contract:
their default refs target `HTMLDivElement`, while `asChild` refs target the
delegated DOM `Element`. Heading defaults to `HTMLHeadingElement`, Text defaults
to `HTMLParagraphElement`, and both expose `Element` refs when delegated.
Collapsible roots likewise use `HTMLDivElement` by default and `Element` when
delegated.

SimpleGrid, Card, Alert, InputGroup, Accordion root/item, and List.Icon/Text now
follow the same default-host/delegated-`Element` ref contract. VisuallyHidden
uses `HTMLSpanElement` by default and `Element` when delegated. InputGroup addon
and element slots require one non-void React element for direct delegation;
invalid `asChild` content falls back to the default div.

## Behavior API aliases

Use the canonical behavior APIs and imports:

State ownership for ListboxSelect, RangeSlider, DatePicker, WheelPicker,
OTPInput, and FileUploader now lives in their feature behavior subpaths.
Reusable integrations can import `useListboxSelectState`,
`useRangeSliderState`, `useDatePickerState`, `useWheelPickerState`,
`useOtpInputState`, and `useFileUploadState` from the corresponding
`@poffy-ui/behavior/*/react` entry. The sibling feature entry remains
server-safe for pure utility imports. React component props remain unchanged.

| Removed                                          | Replacement                     |
| ------------------------------------------------ | ------------------------------- |
| `buildPaginationRange`                           | `buildPaginationItems`          |
| `PaginationDot`                                  | `PaginationEllipsis`            |
| `PaginationRangeItem`                            | `PaginationItem`                |
| `BuildPaginationRangeOptions`                    | `BuildPaginationItemsOptions`   |
| `@poffy-ui/behavior/calendar` date helpers       | `@poffy-ui/behavior/date`       |
| `@poffy-ui/behavior/logic` calendar grid symbols | `@poffy-ui/behavior/calendar`   |
| `@poffy-ui/behavior/logic` date symbols          | `@poffy-ui/behavior/date`       |
| `@poffy-ui/behavior/logic` pagination symbols    | `@poffy-ui/behavior/pagination` |
| `useDropdown().setDisabledIndex`                 | `useDropdown().reconcileItems`  |

`reconcileItems` accepts the complete ordered item snapshot rather than one
disabled index. React Pagination also removes its `PaginationDot` and
`PaginationRangeItem` type aliases; import canonical item types from
`@poffy-ui/behavior/pagination`.

## ScrollArea props

`ScrollAreaProps` is the canonical, non-generic component prop type.
`ScrollAreaRootProps` and the former unused element generic are removed.
The internal viewport now exclusively owns the region role, accessible name,
tab stop, and scroll events. Replace root `tabIndex` with `viewportTabIndex`;
`aria-label`, `aria-labelledby`, `aria-describedby`, `onScroll`, and
`onScrollCapture` target the viewport. Root `role` is no longer supported.

## Tooltip overflow

Tooltip content is now bounded by the available viewport height and becomes
scrollable when supplemental text cannot fit. Pointer and touch users can scroll
the content directly; while focus remains on the trigger, keyboard users can use
Page Up, Page Down, Home, and End. Keep tooltip text short, and use Popover for
long-form or interactive content.

## Calendar labels

Complete dictionaries typed as `CalendarLabels` must add `unavailable`.
Overrides passed directly to `Calendar` remain partial:

```ts
const labels: CalendarLabels = {
  calendar: 'Appointment calendar',
  unavailable: 'This date is unavailable.',
  today: 'Today',
  goToToday: 'Go to today',
  previousMonth: 'Previous month',
  nextMonth: 'Next month',
  selectMonth: 'Select month',
  selectYear: 'Select year',
};
```

Calendar selection defaults now follow the same discriminated contract as
controlled selections:

```tsx
<Calendar defaultValue={date} />
<Calendar mode="multiple" defaultValue={[firstDate, secondDate]} />
<Calendar mode="range" defaultValue={{ from: firstDate, to: secondDate }} />
```

Calendar now owns a fixed native `div` root. Remove `asChild` wrappers and put
layout or semantic containers outside Calendar. Multiple selections are
canonicalized by local calendar day, so duplicates collapse to the first
occurrence. Range values and submitted `_from`/`_to` fields are ordered
chronologically even when a controlled range is supplied in reverse.

Do not mix a mode with another mode's value shape. Day-label formatting accepts
date-only `Intl` options; time and time-zone fields are intentionally ignored
at runtime and no longer accepted by the public type.

DatePicker uses the same shared `DateOnlyFormatOptions` contract. Remove
`timeStyle`, time component, and `timeZone` fields from DatePicker
`formatOptions`; date-only values are formatted as local calendar days.

## Canonical wrapper variant types

Exported `NavbarVariants`, `OTPInputVariants`, `AccordionVariants`,
`PaginationVariants`, `StepperVariants`, `SidebarVariants`, and
`AvatarVariants` now mirror the corresponding component props instead of raw
Panda recipe inputs. Use canonical `appearance`, `intent`, and `shape` values.
Stateful or structural axes such as Stepper `orientation` and Sidebar
`collapsed` are scalar rather than responsive objects.

## DiffViewer modified lines

Modified lines now provide complete unified and split representations:

```tsx
// Before
const line = {
  kind: 'modified',
  content: 'mode: review',
};

// 0.2
const line = {
  kind: 'modified',
  content: 'mode: review',
  oldContent: 'mode: draft',
  newContent: 'mode: review',
};
```

Added, removed, and unchanged lines continue to use only `content`.

## Table `asChild` semantics

Table slots preserve `asChild` only when the child is the matching native table
element. In particular, migrate header cells from `Table.Cell asChild` to the
dedicated header slot:

```tsx
// Before
<Table.Cell asChild>
  <th scope="col">Name</th>
</Table.Cell>

// 0.2
<Table.HeaderCell scope="col">Name</Table.HeaderCell>
```

This keeps the rendered table structure valid when a wrapper passes an
incompatible child. Matching usages such as `Table.Cell asChild` with a `td`
continue to preserve the child.

## Responsive navigation

Pagination now fills its parent inline size instead of subtracting an assumed
viewport gutter. Put page-level safe-area spacing or gutters on the surrounding
layout.

Horizontal Stepper labels now wrap inside bounded steps. At 30rem or narrower,
the visual step layout reflows vertically; wider constrained rows scroll
locally rather than permanently truncating titles and descriptions.

## ShadowRoot portals

Anchored floating content now remains in the trigger's `ShadowRoot` by default.
Install `@poffy-ui/react/styles.css` inside every shadow tree that renders Poffy
UI components or portals; styles imported into the document do not cross a
shadow boundary. An explicit `portalContainer` or `PortalProvider` still takes
precedence over the inferred root.

`portalContainer` and `PortalProvider` select DOM ownership, not overlay
geometry. Modal, Drawer, AlertDialog, and Puff remain viewport-scoped; the
modal components also lock their owner document. Their custom portal root and
ancestors must not establish a CSS fixed-position containing block through
`transform`, `filter`, `perspective`, paint/layout containment, non-normal
`container-type`, `content-visibility: auto`, or matching `will-change`.
Development builds warn when this incompatible configuration is detected.

Form reset subscriptions, overlay focus return, composite focus preservation,
and TimePicker rejected-change recovery now resolve IDs and active elements
within the component's Document or ShadowRoot tree scope.

## Collapsible state and time-group ownership

Controlled Collapsible state now requires `open` and `onOpenChange` together.
Use `defaultOpen` only for uncontrolled state. Untyped `open`-only callers use
that value as the uncontrolled initial state and receive a development warning
instead of creating a frozen disclosure.

`Collapsible.Root` now owns the disabled state. Move `disabled` from
`Collapsible.Trigger` to the root. The trigger also owns its generated identity,
disclosure ARIA, tab position, state marker, role, and button type. Its default
branch exposes an `HTMLButtonElement` ref and button event targets; a valid
`asChild` branch exposes `HTMLElement` ref and event targets.

TimePicker and TimeClock derive required and read-only semantics from their
`required` and `readOnly` props. Remove `aria-required` and `aria-readonly` from
the outer group; the applicable input, listbox, or radiogroup descendants own
those states.
Clock interaction also follows native disabled-fieldset state at event time.
Disabling a fieldset during a drag cancels the active pointer interaction and
does not commit a stale value.

## Accordion, Tabs, and TreeView state ownership

Accordion state is now discriminated by both ownership and mode:

- single controlled: `multiple` omitted/false, `value: string | null`, and
  `onChange`;
- single uncontrolled: `defaultValue?: string | null`;
- multiple controlled: `multiple: true`, `value: string[]`, and `onChange`;
- multiple uncontrolled: `multiple: true` and `defaultValue?: string[]`.

Controlled branches reject `defaultValue`. A closed single Accordion reports
`null` instead of the ambiguous empty string. The same four branches are
exported by `@poffy-ui/behavior/accordion`. AccordionTrigger now owns its fixed
button type, disclosure ARIA, disabled state, identity, and tab position.

Tabs likewise requires `value` and `onValueChange` together and rejects
`defaultValue` on the controlled branch. TreeView applies the rule independently
to `expandedIds`/`onExpandedChange` and `selectedIds`/`onSelectedChange`, so
either axis can remain uncontrolled.

Untyped Tabs callers that provide `value` without a callable `onValueChange`
remain controlled and read-only and receive a development warning. This
fail-closed behavior prevents user interaction from diverging from the supplied
value. Accordion and TreeView retain their documented malformed-pair fallback.

Accordion item values must be unique, and each item must contain exactly one
trigger and one content region. Duplicate values or parts now fail closed:
ambiguous triggers are disabled, ambiguous panels remain closed, and invalid
ARIA references are omitted. Collapsible applies the same exactly-one
trigger/content rule.

Checkbox groups likewise require unique item values. Every occurrence of an
ambiguous value is disabled and excluded from checked state and native form
submission. `Checkbox.Control` and `Checkbox.Label` now use fixed `span` hosts;
remove `asChild` and place inline presentation elements inside them.

## Input controlled-state contracts

Controlled values now require their matching update callback, while
uncontrolled usage accepts `defaultValue` and an optional callback. Controlled
and default values cannot be supplied together.

This applies to `RangeSlider`, `ToggleButton`, `MultiSelect`, `DatePicker`,
`DateTimePicker`, `NumberInput`, `WheelPicker`, `Checkbox` roots and groups,
`RadioGroup`, `OTPInput`, `TimeClock`, and `TimePicker`. Use the corresponding
`onValueChange`, `onPressedChange`, or `onChange` callback for each component.

Untyped value-only or non-callable-handler inputs remain controlled and
read-only, emit a development warning, and never reinterpret the value as an
uncontrolled seed. Controlled-to-uncontrolled handoff uses the latest
canonical value without emitting a callback.

Collection inputs normalize malformed runtime values to safe controlled empty
collections, remove non-string entries and duplicates, and return defensive
copies from callbacks. `WheelPicker` also preserves pending scroll commits
across semantically equivalent parent rerenders. It recenters after its own
layout changes without cancelling pending scroll commits in sibling columns.
Time and number inputs no longer emit callbacks when a user operation resolves
to the current canonical value.

Portaled `ComboBox`, `MultiSelect`, and custom `DatePicker` overlays now close
and reject interaction when their form-associated control becomes disabled by
a surrounding native fieldset. `TreeView.Checkbox` calls the consumer
`onChange` before committing its checked state; calling `preventDefault()`
cancels the tree selection change and restores the native checkbox state.

`RangeSlider` now reserves endpoint space for both the selected thumb size and
its focus ring. Custom layouts that clip the track can rely on the component to
keep focused endpoint rings inside its own inline bounds.

## Polymorphic host, ref, and event contracts

Delegated layout, surface, typography, and accessibility hosts now type DOM
event `currentTarget` as `Element` unless the accepted host set is narrower.
Handlers that assumed the old default `HTMLDivElement`/`HTMLSpanElement` target
must narrow the actual rendered host before using host-specific properties.

- `FormControl` rejects `label` together with `asChild`; untyped combinations
  safely use the native div root. Its group role is managed.
- `FormLabel` now owns a fixed native `label` host. Remove `asChild`; compose
  label content inside the fixed label instead.
- `Avatar` delegates only to supported HTML container hosts and publishes
  separate span and delegated-HTMLElement ref branches.
- `Skeleton` publishes separate native span and delegated host branches while
  retaining its safe runtime host validation.
- `Reference` uses a required `href` branch for anchors and an omitted `href`
  branch for passive spans. Refs and event targets are respectively
  `HTMLAnchorElement` and `HTMLSpanElement`; narrow a `string | undefined`
  destination before constructing props. Unsafe destinations retain the anchor
  host contract but have navigation attributes removed.
- `Link`, `Navbar.Brand`, and `Navbar.Link` distinguish destination anchors,
  no-destination spans, and delegated router links. A no-destination branch no
  longer accepts anchor-only attributes.
- `Button`, `ButtonPrimitive`, and `PressablePrimitive` retain
  `HTMLButtonElement` refs and event targets by default. Their `asChild`
  branches use `HTMLElement` targets and no longer expose native-button-only
  form attributes.
- Modal, Drawer, Popover, and AlertDialog trigger/close controls follow the
  same rule. Keep `form`, `formAction`, `formEncType`, `formMethod`,
  `formNoValidate`, `formTarget`, `name`, and `value` on a native button child,
  not on an `asChild` wrapper. AlertDialog Action and Cancel expose
  `HTMLButtonElement` events and refs by default and `HTMLElement` events and
  refs when delegated.
- Disable a HoverCard at its root. `HoverCard.Trigger disabled` is removed
  because it did not disable the root-owned hover and focus interactions.
- `TabTrigger` and delegated `InputGroup` slots likewise expose event targets
  matching their actual delegated hosts.
- `Dropdown.Item` exposes an `HTMLButtonElement` ref/event target by default
  and an `HTMLElement` ref/event target with `asChild`. Native button-only form
  props stay on the default branch; semantic list menus may delegate items to
  `<li>`, while router-link items retain their link host.

Fixed-host components no longer emit staged `asChild` migration warnings.
Untyped removed props are still consumed at the component boundary so they do
not leak into rendered DOM. ProgressBar custom hosts are now documented as a
formal HTML flow-container forwarding contract rather than a staged legacy
Slot path.

`Spacer` is now always a decorative `div`. Remove `asChild`, children,
focusability, role, and `aria-hidden` overrides. Use `Box` or another layout
primitive when a semantic or interactive flexible item is required.
